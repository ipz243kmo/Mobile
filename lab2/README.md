## 1. Опис проєкту та архітектура

Мобільний застосунок створено на базі фреймворку **React Native** з використанням платформи **Expo**. Проєкт демонструє побудову багатоекранного мобільного інтерфейсу з розмежуванням прав доступу (публічна та приватна зони), ієрархічною навігацією та оптимізованим рендерингом великих наборів даних.

### Ключові модулі та архітектурні рішення:

1. **Глобальне управління станом авторизації (`AuthContext`)**:
   - Реалізовано за допомогою React Context API (`createContext`, `useContext`).
   - Зберігає стан сесії користувача (`isAuthenticated`) та його електронну пошту (`userEmail`).
   - Надає методи `login(email)` (авторизація користувача та збереження облікових даних) і `logout()` (очищення сесії та повернення до екрана входу).
   - Кореневий компонент застосунку обгорнуто в `<AuthProvider>`, що робить стан доступу доступним на будь-якому рівні вкладеності компонентів.

2. **Публічний екран авторизації (`LoginScreen`)**:
   - Доступний виключно неавторизованим користувачам (`isAuthenticated === false`).
   - Містить форму входу з полями для корпоративної електронної пошти (`@student.ztu.edu.ua`) та пароля, а також базову валідацію на заповненість полів.
   - Після успішної перевірки викликає функцію `login()`, що миттєво перемикає кореневий навігатор у захищену зону.

3. **Захищена Drawer-навігація (Бокове меню)**:
   - Реалізує принцип **Protected Routes** (захищених маршрутів): доступ до екранів новин та довідкового центру блокується, якщо користувач не авторизований.
   - Бокова панель містить шапку профілю (ПІБ та email студента), навігаційні пункти для перемикання між основними розділами (*«Стрічка новин»* та *«Довідковий центр (FAQ)»*) і кнопку **«Вийти»**, яка завершує сесію через `logout()`.

4. **Вкладений Stack-навігатор новин**:
   - Працює всередині розділу *«Стрічка новин»* та забезпечує перехід від загального списку новин до сторінки детального перегляду конкретної публікації (`NewsDetailScreen`).
   - Заголовок вкладеного стека приховано (`headerShown: false`), щоб уникнути дублювання панелей навігації із головним заголовком Drawer.
   - При натисканні на картку новини на цільовий екран передається унікальний ідентифікатор `id`, за яким здійснюється пошук та відображення повного тексту статті.

5. **Віртуалізована стрічка новин (`FlatList`) з оптимізацією продуктивності**:
   - Працює з масивом із **120 згенерованих новин** (`ALL_NEWS`).
   - **Пагінація та підвантаження (Infinite Scroll)**: початково завантажується перша сторінка з 20 елементів; при наближенні користувача до нижньої межі списку (`onEndReachedThreshold={0.4}`) спрацьовує подія `onEndReached`, яка плавно підвантажує наступні 20 новин із відображенням індикатора завантаження (`ActivityIndicator`).
   - **Оновлення жестом (Pull-to-Refresh)**: підтримує стандартний мобільний жест потягування списку вниз (`refreshing`, `onRefresh`) для скидання та оновлення стрічки новин.
   - **Оптимізація рендерингу**:
     - `getItemLayout` — заздалегідь обчислює точні координати та висоту кожної картки (`ITEM_HEIGHT = 136`), усуваючи потребу в динамічному вимірюванні розмітки під час швидкого скролінгу.
     - `React.memo` — компонент картки `NewsCard` мемоїзовано, завдяки чому вже відрендерені картки не перемальовуються повторно під час оновлення стану батьківського списку.
     - `useCallback` — обробники подій (`renderItem`, `getItemLayout`, `handleOpenNews`) закешовано для збереження стабільних посилань між рендерами.

6. **Довідковий центр (`SectionList`)**:
   - Відображає базу знань для студентів (запитання та відповіді), структуровану за тематичними категоріями (*«Навчальний процес та розклад»*, *«Технічна підтримка та пошта»*).
   - Використовує компонент `SectionList` із роздільним рендерингом заголовків секцій (`renderSectionHeader`) та карток із запитаннями/відповідями (`renderItem`).

## 3. Інструкція із запуску

### Варіант А: Локальний запуск на комп'ютері (Node.js + Expo CLI)

1. **Клонування репозиторію:**
   ```bash
   git clone [[https://github.com/](https://github.com/)ipz243kmo//MobileLabsRN2026.git](https://github.com/ipz243kmo/Mobile/lab2)
   cd Mobile/lab2
   ```

2. **Встановлення залежностей:**
   ```bash
   npm install
   ```

3. **Запуск сервера розробки Metro Bundler:**
   - **Стандартний запуск (для смартфона в одній Wi-Fi мережі з ПК):**
     ```bash
     npx expo start
     ```
     Після появи QR-коду в терміналі відскануйте його через додаток **Expo Go** (Android) або стандартну камеру (iOS).
   - **Запуск в емуляторі Android (Android Studio AVD):**
     ```bash
     npx expo start --android
     ```
   - **Запуск через тунельоване з'єднання (якщо ПК і телефон у різних мережах або блокуються порти):**
     ```bash
     npx expo start --tunnel
     ```
   - **Запуск із очищенням кешу збирача (у разі помилок кешування):**
     ```bash
     npx expo start --clear
     ```

### Варіант Б: Запуск в онлайн-середовищі Expo Snack (без встановлення ПЗ)
1. Перейдіть на сайт [https://snack.expo.dev](https://snack.expo.dev).
2. Вставте код із файлу `App.js` у редактор коду.
3. Переглядайте роботу застосунку у вбудованому веб-емуляторі праворуч або натисніть **My Device** та відскануйте QR-код через **Expo Go** на фізичному смартфоні.

### Висновки
Під час виконання лабораторної роботи №2 було набуто практичних навичок проєктування архітектури мобільних застосунків на React Native. Реалізовано систему авторизації з захищеними маршрутами на базі React Context, що унеможливлює доступ до приватних екранів без входу в систему. Також було досліджено методи оптимізації продуктивності довгих списків у `FlatList`: застосування віртуалізації, мемоїзації компонентів (`React.memo`) та попереднього розрахунку геометрії елементів (`getItemLayout`) дозволяє підтримувати стабільну частоту кадрів (60 FPS) навіть при роботі зі списками на понад 100 записів.

### Відповіді на контрольні запитання

#### 1. Як працює вкладена навігація в архітектурі Expo Router?
В архітектурі **Expo Router** навігація побудована за принципом файлової маршрутизації (*File-based Routing*), де структура каталогів і файлів у папці `app/` безпосередньо визначає карту переходів застосунку.
- Кожна папка, що містить спеціальний файл `_layout.jsx`, ініціалізує окремий навігатор (`Stack`, `Tabs` або `Drawer`) для всіх дочірніх маршрутів усередині цієї папки.
- Використання директорій у круглих дужках — **груп маршрутів** (наприклад, `(drawer)` або `(news)`) — дозволяє вкладати один навігатор в інший (наприклад, `Stack` усередині `Drawer`) та розділяти макети екранів без додавання назви самої групи до URL-шляху.

#### 2. Яким чином реалізується захист маршрутів від неавторизованого доступу?
Захист маршрутів (**Protected Routes**) реалізується шляхом поєднання глобального стану авторизації та декларативного перенаправлення:
1. Створюється глобальний контекст (`AuthContext`), який зберігає булевий прапорець `isAuthenticated` та методи зміни стану (`login()`, `logout()`).
2. Кореневий макет застосунку обгортається у провайдер цього контексту.
3. У файлі `_layout.jsx` захищеної групи маршрутів (`app/(drawer)/_layout.jsx`) виконується перевірка стану `isAuthenticated`. Якщо користувач не авторизований (`!isAuthenticated`), компонент одразу повертає `<Redirect href="/login" />` (або рендерить публічний компонент входу), блокуючи доступ до приватних екранів навіть при спробі прямого переходу за посиланням.

#### 3. Чим FlatList відрізняється від ScrollView та що таке віртуалізація списків?
- **`ScrollView`** рендерить усі дочірні компоненти одночасно під час першого завантаження екрана, незалежно від того, чи бачить їх користувач зараз. На великих списках (сотні чи тисячі елементів) це призводить до критичного споживання оперативної пам'яті, затримок при відкритті екрана та падіння FPS.
- **`FlatList`** використовує механізм **віртуалізації списків** (*VirtualizedList*). Віртуалізація означає, що в пам'яті та на екрані створюються й відображаються лише ті елементи, які в даний момент потрапляють у видиму область вікна перегляду (плюс невеликий буфер зверху та знизу для плавності прокрутки). Коли користувач гортає список, елементи, що вийшли за межі екрана, розмонтовуються (пам'ять звільняється), а на їхньому місці рендеряться нові елементи.

#### 4. Як отримати параметри динамічного маршруту на цільовому екрані в Expo Router?
Для створення динамічного маршруту в Expo Router ім'я файлу береться у квадратні дужки, наприклад `app/(drawer)/(news)/[id].jsx`. Під час переходу на цей маршрут передається конкретне значення (наприклад, `router.push('/news/42')`).
На цільовому екрані значення динамічного параметра отримується за допомогою спеціального хука **`useLocalSearchParams()`**, який імпортується з бібліотеки `expo-router`:
```javascript
import { useLocalSearchParams } from 'expo-router';

export default function NewsDetailScreen() {
  const { id } = useLocalSearchParams(); // Отримаємо id = '42'
  // ...
}
```

#### 5. Яку структуру даних приймає компонент SectionList?
Компонент **`SectionList`** призначений для відображення згрупованих списків із заголовками розділів. У свою обов'язкову властивість `sections` він приймає **масив об'єктів**, де кожен об'єкт описує одну окрему секцію та обов'язково містить властивість `data` (масив елементів цієї секції) і довільні поля для заголовка секції (найчастіше `title`):
```javascript
const SECTIONS_DATA = [
  {
    title: 'Назва секції 1',
    data: [
      { id: '1', question: 'Запитання 1', answer: 'Відповідь 1' },
      { id: '2', question: 'Запитання 2', answer: 'Відповідь 2' },
    ],
  },
  {
    title: 'Назва секції 2',
    data: [
      { id: '3', question: 'Запитання 3', answer: 'Відповідь 3' },
    ],
  },
];
```
