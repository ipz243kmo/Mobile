# Лабораторна робота №3 — Expo Router: кастомізація навігаційних компонентів, нативні модальні вікна та віртуалізація списків

**Дисципліна:** Розробка мобільних застосунків (React Native / Expo)  
**Тема:** Expo Router: кастомізація навігаційних компонентів, нативні модальні вікна та віртуалізація списків.  
**Мета:** Закріплення практичних навичок використання файлової маршрутизації Expo Router, проєктування ієрархічних систем навігації та застосування компонента `VirtualizedList` для оптимізованого рендерингу списків даних.

## 1. Опис проєкту та архітектура

Прототип модуля адміністрування порталу новин розроблено на базі **React Native** та **Expo Router**. Застосунок реалізує повний цикл управління контентом (CRUD), адміністрування облікових записів користувачів, аудит системних подій, нативні модальні вікна та оптимізовану віртуалізацію великих масивів даних із дотриманням безпечних зон екрана (`react-native-safe-area-context`).

### Реалізовані модулі та функціонал:
1. **Авторизація та захищена група маршрутів (`login.jsx`, `(admin)/_layout.jsx`)**:
   - Реалізовано публічний екран входу адміністратора з валідацією полів та перенаправленням у захищену групу маршрутів `(admin)`.
   - За відсутності активної сесії (`isAuthenticated === false`) виконується автоматичне перенаправлення на сторінку входу через компонент `<Redirect href="/login" />`.
2. **Кастомізоване бокове меню (`AdminDrawerContent`)**:
   - Підключено до навігатора `<Drawer>` через властивість `drawerContent={(props) => <AdminDrawerContent {...props} />}`.
   - Містить блок профілю адміністратора (аватар, ПІБ, корпоративний email), пункти навігації (*Дашборд*, *Новини*, *Користувачі*, *Системні логи*) та кнопку **«Вийти»** у нижній частині панелі.
3. **Дашборд аналітики (`(admin)/index.jsx`)**:
   - Відображає зведену статистику порталу: загальну та опубліковану кількість новин, загальну та активну кількість користувачів, а також лічильник системних логів.
   - Використовує хук **`useFocusEffect`** для автоматичної актуалізації показників при кожному фокусуванні на екрані.
4. **Віртуалізовані списки (`VirtualizedList`)**:
   - Для управління даними новин, облікових записів користувачів та журналу системних логів згенеровано по **55 записів** у локальних масивах стану.
   - Усі три списки побудовано на базі низькорівневого компонента **`VirtualizedList`** з бібліотеки `react-native` із параметрами оптимізації `getItemCount`, `getItem` та `getItemLayout` для миттєвого обчислення висоти й координат елементів без зайвих перемальовувань.
5. **Управління новинами та нативні модальні вікна (`presentation: 'modal'`)**:
   - Детальний перегляд новини реалізовано за динамічним маршрутом `/news/[id]` із отриманням ідентифікатора `id` через хук **`useLocalSearchParams()`**.
   - Створення та редагування публікацій винесено в окремий екран `news-modal.jsx`, зареєстрований із параметром **`presentation: 'modal'`** (містить поля: Заголовок, Категорія, Статус — *Опубліковано*, *Чернетка*, *На перевірці*, URL зображення та Текст новини).
   - Видалення новини супроводжується підтвердженням через нативний діалог **`Alert.alert()`**.
6. **Панель фільтрації (`presentation: 'formSheet'`)**:
   - Реалізовано екран `filter-sheet.jsx` у режимі нативного нижнього листа (`presentation: 'formSheet'`) із налаштуванням висоти фіксації `sheetAllowedDetents: [0.45, 0.8]` для швидкої фільтрації новин і користувачів за статусом.
7. **Журнал системних логів (Аудит подій)**:
   - Автоматично додає новий запис у масив логів при настанні 6 системних подій:
     1. Вхід у систему;
     2. Вихід із системи;
     3. Створення новини;
     4. Редагування новини;
     5. Видалення новини;
     6. Зміна статусу користувача (*Активний* / *Заблокований*).

## 3. Інструкція із запуску

### Варіант А: Локальний запуск на комп'ютері (Node.js + Expo CLI)
1. **Клонуйте репозиторій та перейдіть до папки `lab3`:**
   ```bash
   git clone https://github.com/ipz243kmo/Mobile/lab3
   cd Mobile/lab3
   ```
2. **Встановіть залежності проєкту:**
   ```bash
   npm install
   ```
3. **Запустіть локальний сервер розробки Expo:**
   - `npx expo start` — стандартний запуск сервера розробки (для підключення смартфона через **Expo Go**);
   - `npx expo start --android` — запуск безпосередньо в емуляторі Android (AVD);
   - `npx expo start --tunnel` — запуск через тунельоване з'єднання (якщо ПК і смартфон знаходяться в різних мережах або блокується локальний Wi-Fi);
   - `npx expo start --clear` — запуск із попереднім очищенням кешу збирача Metro Bundler.

### Варіант Б: Запуск в онлайн-середовищі Expo Snack
Відкрийте проєкт на сайті [https://snack.expo.dev](https://snack.expo.dev) та запустіть його у вбудованому прев'ю або відскануйте QR-код через мобільний застосунок **Expo Go**.

## 5. Висновки та відповіді на контрольні запитання

### Висновки
Під час виконання лабораторної роботи №3 було закріплено практичні навички проєктування багатоекранної архітектури застосунків на базі файлової маршрутизації **Expo Router**. Поєднання захищеного `Drawer`-навігатора з кастомізованим меню, вкладеного `Stack` із динамічними маршрутами (`[id]`), а також нативних модальних вікон (`modal` та `formSheet`) дозволило реалізувати повноцінний модуль адміністрування порталу новин. Використання компонента `VirtualizedList` із функціями `getItemCount`, `getItem` та `getItemLayout` забезпечило високу швидкодію рендерингу списків на 50+ елементів, а застосування хука `useFocusEffect` гарантувало своєчасну актуалізацію аналітичних даних на дашборді.

### Відповіді на контрольні запитання

#### 1. Яким чином виконується кастомізація бічного меню та хедера стекової навігації за допомогою `drawerContent` та `screenOptions.header`?
- **Кастомізація бічного меню (`drawerContent`)**: Навігатору `<Drawer>` передається функція `drawerContent={(props) => <AdminDrawerContent {...props} />}`, яка замінює стандартний макет бокової панелі власним React-компонентом. Усередині цього компонента використовується контейнер `<DrawerContentScrollView {...props}>`, стандартний список маршрутів рендериться через `<DrawerItemList {...props} />`, а зверху та знизу додаються кастомні блоки інтерфейсу (картка профілю адміністратора, бейджі ролі та кнопка «Вийти»).
- **Кастомізація хедера стекової навігації (`screenOptions.header`)**: У навігаторі `<Stack>` через властивість `screenOptions={{ header: (props) => <CustomHeader {...props} /> }}` можна повністю замінити стандартну верхню панель на власний компонент із кастомними елементами керування (кнопками дій, пошуком, логотипом) або налаштувати її стилізацію за допомогою опцій `headerStyle`, `headerTintColor`, `headerTitle` та `headerRight`.

#### 2. У чому відмінність між нативними режимами модальних вікон `presentation: 'modal'` та `presentation: 'formSheet'`?
- **`presentation: 'modal'`**: Відкриває екран як повноцінне модальне вікно, яке на iOS виїжджає знизу вгору у вигляді картки з невеликим відступом від верхнього краю екрана (залишаючи фон попереднього екрана трохи затемненим позаду), а на Android відображається поверх поточного стека. Цей режим найкраще підходить для об'ємних форм створення або редагування записів.
- **`presentation: 'formSheet'`**: Відкриває екран у вигляді нативного нижнього листа (**Bottom Sheet**), висоту якого можна гнучко обмежувати за допомогою масиву `sheetAllowedDetents` (наприклад, `[0.45, 0.8]` — 45% або 80% висоти екрана) та доповнювати індикатором перетягування (`sheetGrabberVisible: true`). Ідеально підходить для компактних панелей фільтрації або швидких налаштувань, зберігаючи візуальний контекст основного екрана.

#### 3. Для чого використовується хук `useFocusEffect` і чим він відрізняється від стандартного `useEffect`?
- **Призначення `useFocusEffect`**: Хук із бібліотеки `expo-router` (або `@react-navigation/native`) запускає побічний ефект щоразу, коли екран **отримує фокус** (користувач переходить на нього), і викликає функцію очищення (cleanup), коли екран **втрачає фокус**.
- **Відмінність від `useEffect`**: У мобільній навігації (Stack, Tabs, Drawer) екрани залишаються змонтованими в пам'яті у фоновому режимі навіть після переходу на інший екран. Стандартний хук `useEffect(..., [])` спрацьовує лише один раз під час першого монтування компонента і не виконується повторно при поверненні користувача назад. Натомість `useFocusEffect` гарантує оновлення даних (наприклад, перерахунок статистики новин, користувачів та логів на дашборді) при кожному повторному відкритті екрана.
