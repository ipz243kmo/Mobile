# Лабораторна робота №5 — Робота з файловою системою в React Native з використанням бібліотеки `expo-file-system`

**Виконала:** Куліш Марія Олександрівна, група ІПЗ-24-3  
**Дисципліна:** Розробка мобільних застосунків (React Native / Expo)  
**Тема:** Робота з файловою системою в React Native з використанням бібліотеки `expo-file-system`.  
**Мета:** Опанувати механізми роботи з локальною файловою системою мобільного пристрою, використовуючи можливості бібліотеки `expo-file-system`. Закріпити навички реалізації базових операцій над файлами й папками, організації файлової навігації та аналізу стану файлової системи.

---

## 1. Опис проєкту та архітектура

Мобільний застосунок **«Файловий менеджер»** розроблено на базі **React Native**, **Expo Router** та сучасного об'єктно-орієнтованого API бібліотеки **`expo-file-system`** (класи `File`, `Directory`, `Paths`) із дотриманням безпечних зон екрана (`react-native-safe-area-context`).

### Реалізовані функціональні можливості:
1. **Статистика використання пам'яті пристрою (`app/index.jsx`)**:
   - За допомогою властивостей `Paths.totalDiskSpace` та `Paths.availableDiskSpace` отримується та форматується інформація про **загальний**, **зайнятий** та **вільний** обсяг сховища мобільного пристрою.
2. **Навігація по локальній файловій системі (`Paths.document`)**:
   - Відображення поточного шляху у вигляді навігаційного рядка (breadcrumb).
   - Відображення вмісту поточної директорії через компонент **`FlatList`** із візуальним розділенням папок та файлів і сортуванням (спочатку директорії, потім файли).
   - Перехід у вкладені директорії при натисканні на папку та повернення назад за допомогою кнопки **«Вгору»**.
3. **Створення файлів та папок**:
   - Модальне вікно з полями `TextInput` для створення нових директорій (`new Directory(...).create()`) та текстових файлів `.txt` із початковим вмістом (`new File(...).create()`, `file.write()`).
4. **Зчитування та редагування `.txt` файлів (`app/editor.jsx`)**:
   - Відкриття текстових файлів в окремому модальному екрані, зчитування тексту через метод `file.text()`, модифікація у багаторядковому `TextInput` та збереження змін через `file.write()`.
5. **Видалення об'єктів із підтвердженням**:
   - Видалення обраного файлу (`file.delete()`) або директорії (`dir.delete()`) здійснюється лише після підтвердження користувачем у нативному діалоговому вікні **`Alert.alert()`**.
6. **Перегляд детальної інформації про файл (`app/details.jsx`)**:
   - Виведення метаданих об'єкта (через `target.info()`): назва файлу, тип файлу за розширенням, розмір у байтах/КБ/МБ, дата останньої модифікації та повний URI.

### Висновки
Під час виконання лабораторної роботи №5 було опановано сучасний API бібліотеки `expo-file-system` для роботи з локальною файловою системою мобільного пристрою. Реалізовано повноцінний файловий менеджер із переглядом статистики дискового простору, навігацією по ієрархії каталогів, створенням, читанням, редагуванням і видаленням файлів та папок, а також отриманням їхніх метаданих.

### Відповіді на контрольні запитання

#### 1. Які основні директорії надає бібліотека `expo-file-system` (зокрема `documentDirectory` та `cacheDirectory`) і в чому полягає різниця між ними?
Бібліотека `expo-file-system` (через `Paths.document` / `Paths.cache`) надає дві основні ізольовані директорії (sandbox) для кожного застосунку:
- **`Paths.document` (`documentDirectory`)** — постійна директорія для зберігання важливих користувацьких даних та файлів, створених у процесі роботи застосунку. Файли в цій папці зберігаються протягом усього життєвого циклу застосунку до моменту, поки користувач сам їх не видалить або не видалить сам додаток (а також можуть включатися до резервних копій iCloud/Android Backup).
- **`Paths.cache` (`cacheDirectory`)** — тимчасова директорія для кешування даних (наприклад, завантажених зображень, тимчасових документів або мережевих відповідей). Операційна система Android або iOS має право автоматично очистити вміст цієї директорії в будь-який момент, якщо на пристрої закінчується вільний простір.

#### 2. Які базові методи `expo-file-system` використовуються для читання, запису, створення директорій та видалення файлів і папок?
У сучасному об'єктно-орієнтованому API `expo-file-system` використовуються класи **`File`** та **`Directory`**:
- **Створення директорій**: `const dir = new Directory(Paths.document, 'folderName'); dir.create();` (опція `{ intermediates: true }` дозволяє створювати одразу весь ланцюжок вкладених папок).
- **Створення та запис у файл**: `const file = new File(dir, 'note.txt'); file.create(); file.write('Текст файлу');`.
- **Читання вмісту файлу**: `const text = file.text();` (або асинхронно `await file.text()` / `file.bytes()` для бінарних даних).
- **Отримання списку вмісту директорії**: `const entries = dir.list();` (повертає масив екземплярів `File` та `Directory`).
- **Видалення файлів та папок**: `file.delete()` для видалення файлу та `dir.delete()` для видалення директорії разом із її вмістом.

#### 3. Як отримати метадані про об'єкт файлової системи (розмір, дату останньої модифікації) та інформацію про загальний і вільний обсяг пам'яті пристрою?
- **Метадані файлу або директорії**: викликається метод **`.info()`** на екземплярі `File` або `Directory` (наприклад, `const info = file.info()`), або використовуються прямі властивості об'єкта. Повернений об'єкт містить поля:
  - `exists` (булеве значення існування);
  - `size` (розмір файлу в байтах);
  - `modificationTime` (мітка часу останньої зміни у мілісекундах);
  - `uri` (повний шлях до об'єкта).
- **Інформація про обсяг пам'яті пристрою**: використовуються статичні властивості класу **`Paths`**:
  - `Paths.totalDiskSpace` — повертає загальний обсяг внутрішнього сховища пристрою в байтах;
  - `Paths.availableDiskSpace` — повертає обсяг доступного (вільного) простору в байтах (зайнятий простір обчислюється як різниця `totalDiskSpace - availableDiskSpace`).
